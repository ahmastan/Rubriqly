# Contributing to Rubriqly

Thanks for helping. Bug reports, fixes, rubric ideas and improvements are all welcome.

## Before you start

- For anything bigger than a small fix, **open an issue first** so we can agree on the approach.
- Security problems: please don't open a public issue; see [SECURITY.md](SECURITY.md).

## Set up

Follow "Run it locally" in the [README](README.md). No API keys are needed: the backend uses a mock scorer, and the tests use a throw-away database. [docs/architecture.md](docs/architecture.md) explains how the pieces fit together, and `CLAUDE.md` has detailed conventions.

## Make your change

1. Fork the repo and create a branch.
2. Keep changes focused, and match the style of the surrounding code.
3. Add or update tests for what you change.
4. Run every check before opening a pull request. CI runs the same ones:

   ```bash
   cd rubriqly-backend && uv run ruff check . && uv run ruff format --check . && uv run pytest
   cd rubriqly-frontend && npm run lint && npm run typecheck && npm test && npm run build
   ```

5. Open a pull request that explains what changed and why.

## Rules that keep Rubriqly honest

These are part of the product, and tests enforce several of them:

- Results are always **an estimate, not a grade**.
- Rubriqly **never writes or rewrites** student text.
- Rubric **tips are never sent** to the scoring model.
- Drafts stay in the browser. The server must **never store or log draft text**.
- Scoring failures show a clear error, **never a guessed or partial result**.
- No invented testimonials, statistics or accuracy claims in the site's copy.
- The Privacy Policy (`legal.ts`) must match what the code does. Update it with any change to data handling.

## Things to avoid

- Don't commit secrets, `.env` files or real connection strings. Deployment-specific values are settings; see `render.example.yaml`.
- Don't add real (paid) Jev calls to tests. Use the mock or `httpx.MockTransport`.
- Database changes need an Alembic migration. Review autogenerated ones for Postgres compatibility.
